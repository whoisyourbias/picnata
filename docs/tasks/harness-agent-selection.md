# 사용량과 작업 성격에 따른 Codex·Claude 선택

## 목표

하네스에 자동 선택을 추가할 수 있다. 먼저 작업을 수행할 수 있는 모델과 추론 수준을 고르고, 그 후보 안에서 구독 한도가 더 여유로운 에이전트를 배정한다. 이 문서는 도입 제안이며, 현재 실행 가능한 에이전트 인자는 `codex`와 `claude`다.

## 범위

구독 계정으로 실행하는 명세 작성과 구현·교차 리뷰를 다룬다. 서비스의 음악 추천 모델, API 종량제 비용 배분은 별도 주제다.

## 변경 대상

현재 [오케스트레이터](../../harness/orchestrator.py)는 CLI에 모델이나 추론 수준을 명시하지 않는다. 구현자의 반대쪽 에이전트가 리뷰하고, 검증 단계는 명세의 명령을 실행한다. 향후 구현 후보는 이 오케스트레이터와 [하네스 테스트](../../tests/test_harness.py)다.

## 동작 명세

### 1. 작업에 맞는 후보를 만든다

아래 표는 이 프로젝트에서 시험할 초기 배정 기준이다. 모델 이름은 후보 예시이며 실제 계정과 CLI가 지원하는 조합만 사용한다. 추론 옵션이 없는 모델은 기본값으로 평가한다.

| 작업과 판단 근거 | Codex 후보 | Claude 후보 | 추론 수준 |
| --- | --- | --- | --- |
| 이미 결정된 API 필드 설명을 문서에 반영한다. 원문과 결과를 직접 대조할 수 있다. | 경량 모델 | Haiku | 지원되는 최저 수준 |
| Spring API 입력 검증과 경계값 테스트를 추가한다. 계약과 실패 조건이 명세에 있다. | 범용 코딩 모델(예: GPT-6.2 Sol) | Sonnet | 낮음으로 시작, 필요 시 중간 |
| 작업 잠금·재시도·커밋 복구를 함께 변경하거나 리뷰한다. 여러 상태 전이에서 중복 실행 가능성을 따져야 한다. | 상위 추론 모델(예: GPT-6.2 Astra) | Opus | 중간으로 시작, 필요 시 높음 |
| 승인된 명세의 검증 명령을 실행한다. | 하네스가 직접 실행 | 하네스가 직접 실행 | 해당 없음 |

같은 ‘문서 작성’도 이미 결정된 내용을 옮기면 첫 행, 장애 복구 규약을 새로 설계하면 셋째 행에 해당한다. 리뷰도 변경의 실패 영향을 기준으로 배정한다. 모델별 우열은 이 저장소에서 측정해야 한다. 같은 난이도의 완료 작업에서 첫 검증 통과율, 리뷰 후 재작업 횟수, 소요 시간을 모델·추론 설정과 함께 비교해 표를 조정한다.

단계별로 표의 시작 수준을 적용한다. 해석할 요구사항이나 상태 전이가 여러 개라면 처음부터 해당 행의 모델을 사용한다. 추론 수준은 각 CLI와 모델이 실제 지원하는 값으로 매핑한다. 지원하지 않는 시작 수준은 지원되는 바로 위 수준으로 올리고, 조절 옵션이 없으면 모델 기본값을 기록한다.

검증 실패나 리뷰 지적의 원인을 현재 설정에서 분석했지만 해결하지 못했고, 미해결 항목과 근거가 기록되면 다음 시도에서 추론을 한 단계 높인다. 더 높은 수준이 없을 때만 상위 모델 후보로 전환한다. 자동 상향은 단계당 한 번으로 제한한다. 인증·구독 한도·환경 오류에는 상향을 적용하지 않는다. 구독 잔여율은 같은 단계의 요구 모델과 시작 추론 수준을 만족하는 후보 사이에서 배정에 사용한다.

### 2. 구독 한도에서 읽을 수 있는 값

- **Codex**는 ChatGPT 로그인 환경의 App Server에서 `account/rateLimits/read`로 한도 구간별 사용률과 초기화 시각을 조회할 수 있다. 실행에 사용할 계정과 모델에 적용되는 구간을 읽는다. [OpenAI App Server](https://developers.openai.com/codex/app-server)
- **Claude Code**는 실행과 같은 계정·환경에서 `claude -p "//usage"`를 호출해 사용률을 확인한다. 사용자가 제공한 비대화형 출력에서 `Current session`은 88% 사용(잔여 12%), `Current week (all models)`는 12% 사용(잔여 88%)이었다. 두 행에서 사용률과 초기화 시각을 추출한다. `What's contributing to your usage?` 이하의 요청 수와 비율은 로컬 활동 요약이므로 배정에 사용하지 않는다. 확인된 출력은 영문 형식이며, 지원하지 않는 출력 형식, 중복·누락 행, 범위를 벗어난 사용률, 해석할 수 없는 초기화 시각, 명령 실패 또는 시간 초과는 ‘미확인’으로 처리한다. 모델에 별도 한도가 적용되어 해당 값을 확인할 수 없는 경우에도 ‘미확인’으로 처리한다.
- 단계별로 CLI가 제공하는 입력·출력·캐시·추론 토큰을 가용한 항목만 기록한다. 캐시·추론이 입출력 합계에 포함된 경우 중복 합산하지 않는다. 미보고 항목은 미확인으로 표시한다. 초기 실행과 재시도를 합친 토큰 사용량을 같은 작업 유형·제공자 내에서 비교하고 첫 검증 통과율과 함께 시작 설정을 조정한다. 두 구독의 잔여율 50%가 같은 작업량을 보장하지 않으므로 잔여율은 한도에 가까운 쪽을 피하는 신호로 해석한다.

### 3. 선택과 실패 처리

제안 인터페이스는 기존 명령의 에이전트 자리에 추가하는 `auto`다. 명세 작성은 한 에이전트만 고른다. 구현은 구현자와 상대 리뷰어가 각각 필요한 수준의 모델을 쓸 수 있는 조합만 고른다.

1. 각 후보에 대해 적용되는 구간마다 100에서 사용률을 빼고 가장 작은 잔여율을 취한다. 예를 들어 Codex의 두 구간이 80%, 15% 남고 Claude가 50%, 45% 남았다면 양쪽이 같은 작업을 수행할 수 있을 때 Claude가 구현하고 Codex가 리뷰한다.
2. 어느 구간이든 소진된 후보는 초기화 후 재조회한다. 5분보다 오래된 관측, 조회 실패, 적용 한도 확인 실패는 ‘미확인’으로 표시한다. 명세 작성에서는 확인된 후보를 우선한다. 구현·리뷰 쌍을 확인할 수 없으면 자동 실행을 보류하고 원인과 수동 지정 방법을 표시한다.
3. 잔여율까지 동률이면 Codex를 구현자로 선택한다. 실행 기록에는 선택한 에이전트·모델·추론 수준, 판단에 쓴 잔여율과 관측 시각을 남긴다. 재개 시에는 기록된 구현자를 기준으로 교차 리뷰한다. 실행 도중 한도에 걸리면 마지막으로 완료된 단계에서 재개할 수 있도록 중단한다.

## 완료 조건

향후 구현 시 다음 사례를 고정 입력으로 검증한다.

- [ ] 위의 80/15 대 50/45 사례에서 Claude 구현자와 Codex 리뷰어를 선택한다.
- [ ] 잔여율이 가장 높은 후보도 요구된 추론 수준을 지원하지 않으면 해당 단계에서 제외한다.
- [ ] 한쪽 한도가 소진되거나 관측이 만료되면 자동 구현을 시작하지 않는다. 명시적인 에이전트 지정은 기존 경로로 실행한다.
- [ ] 재개 후 동일 제공자가 자신의 구현을 리뷰하지 않으며 검증 단계는 모델 호출 없이 실행된다.

- [ ] 사용자 제공 영문 출력에서 Claude의 잔여율 12%를 계산하고 로컬 활동 요약을 무시한다. 필수 행이 빠지거나 명령이 시간 초과되면 미확인으로 처리한다.

- [ ] 단순 문서는 경량 모델과 최저 지원 추론, 일반 구현은 범용 모델과 낮은 추론에서 시작한다. 추론 옵션이 없는 모델은 기본값을 기록한다.
- [ ] 미해결 검증·리뷰 항목이 기록되면 다음 시도에서 한 번만 상향한다. 인증·한도·환경 오류에는 상향하지 않는다.

## 검증 명령

python -m unittest discover -s tests -p test_harness.py

## 가정

사용량은 구독 한도 잔여율로 해석했다. 5분 유효기간, 동률 처리, 작업별 모델 표는 초기 운영값이다. Claude 조회 경로는 사용자가 제공한 출력에 근거한다. 이 환경에서 명령을 재실행하거나 다른 CLI 버전·언어의 출력, 모델별 성능을 검증하지 않았다.
